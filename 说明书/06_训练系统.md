## 6.13 显存优化方案（3090 24GB 跑 8B 全参训练）

> **环境**：本地 WSL（Ubuntu 24.04）RTX **3090 Ti 24GB**（5-29 GPU 直通验证，torch 2.12.0+cu130）。PT / 身份SFT / 工具链GRPO / v9d 全部在这块卡上跑。
> **难点**：8B 全参 bf16 权重就 16GB，24GB 余量仅 8GB——**装不下 Adam 优化器状态**（8B 的 Adam 状态 ≈ 16GB@8bit / 64GB@fp32）。跑通全靠 Lomo。

### 核心：Lomo 优化器（LOw-Memory Optimization，复旦论文）

```python
from lomo_optim import Lomo
optimizer = Lomo(model, lr=LR)      # 三个训练脚本（pretrain_lm/sft_lm/v9d）统一用
```

**原理**：Lomo 用 **SGD 风格逐层更新**——backward 到某一层时**立即 in-place 更新该层参数**，不存储梯度、不存动量/二阶矩（Adam 状态全免）。
- 显存账（8B）：权重 16GB(bf16) + 激活（max_length=512 时很小）+ **零优化器状态** → 24GB 可跑全参
- 特性：backward 时 in-place 更新，`zero_grad()` 不丢梯度（7-19 验证）

### 配套显存优化（全套组合）

| 手段 | 作用 | 使用处 |
|------|------|--------|
| **Lomo 优化器** | 省掉 Adam 状态（~16GB） | 全部训练脚本 |
| **bf16**（torch_dtype=bfloat16） | 权重减半（16GB） | 全部 |
| **max_length=512 截断** | 激活内存极小（短上下文） | sft_lm.py |
| **device_map="auto"** | 层自动分配（必要时 CPU offload） | 全部 |
| **每步 gc.collect() + empty_cache()** | 防显存碎片累积 | sft_lm / v9d |
| **GRPO GROUP_SIZE=2**（1采样+1golden） | batch 极小 | v9d |
| **单条前向+反向**（循环内逐条，不 batch） | 峰值显存最低 | 全部 |

### 显存是"贴着 24GB 跑"的证据

- 08-08：**用户玩游戏抢显存 → LLM 推理 OOM**（训练/推理与游戏共用 3090，余量极小）
- 6-04 推理侧规划：neko-v7(Q8_0 14.2G) + 自主神经(1.4G) + GNDINO(3G) + Qwen2.5-VL(4.4G) = **23G/24G**
- 训练时**不能同时跑推理服务**，否则必 OOM

### 历史：A800 时代（AutoDL 租用，17阶段 + b 系列）

| 项 | A800 80GB（5月底-6月中） | 本地 3090 24GB（6月底至今） |
|----|------------------------|---------------------------|
| 优化器 | AdamW8bit（bitsandbytes） | **Lomo** |
| 显存 | 33.7GB/80GB | ~24GB 贴边 |
| 梯度 | 常规（需存） | 逐层 in-place 更新（不存） |
| 训练框架 | 纯 PyTorch（弃 LLaMA-Factory fp32 upcast） | 纯 PyTorch |

**切换原因**（推断）：A800 是 AutoDL 按时租用（6-17 记录），本地 3090 免费常驻 → 6 月底起 PT/GRPO 全迁本地，靠 Lomo 在 24GB 上跑通 8B 全参。
