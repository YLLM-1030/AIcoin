# 情绪系统 — 踩坑记录

> 2026-06-09 | 调试耗时 ~2h | 最终修复: 2 处

## 坑 1: prompt 格式错误（根因）

**现象**: `measure()` 返回 `KeyError: 'logprobs'`

**错误代码**:
```python
f"{context_text}\n\n基于以上上下文，描述你现在的情绪:"
```

**根因**: `\n\n基于以上上下文，` 破坏了 prompt 结构。Ollama 的 `num_predict=1` 在这个格式下返回空 response、无 logprobs。

**正确代码**:
```python
f"{context_text}。描述你现在的情绪:"
```

**教训**: 测试文件 `test_emotion_raw.py` 和 `test_emotion_logprobs.py` 是参考实现。基线和刺激使用**同一 prompt 格式**——`描述你现在的情绪:`，上下文用 `。` 自然衔接，不加任何额外前缀。

---

## 坑 2: requests.post + json.dumps 中文编码

**现象**: 改动 prompt 后仍然 `KeyError: 'logprobs'`

**错误代码**:
```python
body = json.dumps({...})
resp = requests.post(..., data=body, headers={"Content-Type": "application/json"})
```

**根因**: `json.dumps()` 默认 `ensure_ascii=True`，把中文编码为 `\uXXXX` 转义序列。`requests.post(data=body)` 原样发送，Ollama 的 generate API 不解析转义后的中文 prompt，返回空 response 且无 logprobs。

**正确代码**:
```python
resp = requests.post(..., json={...})
```

**教训**: 调用 Ollama API 时，永远用 `requests.post(json=dict)` 而非 `data=json.dumps(dict)`。curl 的行为和 requests 不同——curl 发送的是字节流，requests 有额外的编码层。

---

## 坑 3: Python 模块缓存

**现象**: 修了代码但行为不变

**根因**: `detector.py` 是启动时 import 的。修改后必须重启整个 v10 进程才能加载新代码。

**教训**: 别在 debug print 上浪费时间。先确认进程已重启。

## 坑 4: Live2D — setParams 全量替换 + 帧循环冲突

> 2026-06-09 | 调试耗时 ~3h | 涉及: `puppet_live2d.html`、`lib/l2d-widget.min.js`

**现象**: 待机呼吸正常，点击情绪按钮无反应（或生效一帧后被覆盖）。

**根因**: 看 l2d-widget 源码 `setParams(e)`:

```javascript
let t = this.live2DMgr.getModel();
t && (t._forcedParams = {...e})  // ← 整体替换，不是合并！
```

idleLoop 每秒 60 帧调用 `po.setParams({ParamBreath: 值})`，把其他参数全部冲掉。

**正确架构 — 三层状态机**:

```javascript
let _emotionParams = {};   // 情绪层（按钮写入）
let _actionParams  = {};   // 动作层（唇同步/眨眼/点头）

function idleLoop() {
  const merged = { ..._emotionParams };
  merged.ParamBreath = 0.03 * Math.sin(t * 0.5);  // 待机
  Object.assign(merged, _actionParams);             // 动作覆盖
  po.setParams(merged);                             // 唯一推送点
}
```

**教训**: `setParams` 不是 update 是 replace。帧循环是唯一推送点，其他逻辑只管写入各自状态层。优先级: `_actionParams > _emotionParams > 待机`。

## 坑 5: Live2D — 眼睛 mesh 消失

> 2026-06-09 | 与坑 4 同时修复

**现象**: 把 `ParamEyeLOpen: 1` 写进每帧的合并推送后，眼睛 mesh 直接不渲染（不是闭眼，是整个消失）。

**错误**:
```javascript
// 每帧都写 ParamEyeLOpen: 1
const merged = { ParamEyeLOpen: 1, ParamEyeROpen: 1, ..._emotionParams };
po.setParams(merged);
```

**正确**:
```javascript
// 启动时写一次
po.setParams({ ParamEyeLOpen: 1, ParamEyeROpen: 1 });
// 帧循环不再碰眼睛参数
```

**推测根因**: Cubism 引擎对反复出现的关键参数有特殊插值/缓存机制。写一次进入稳定态没问题，每帧重复写触发内部状态冲突。

**教训**: baseline 参数（眼/嘴默认值）启动时写一次，帧循环只推变化值。

## 坑 6: Live2D — 情绪切换是"幻灯片"而非动画

> 2026-06-09 | 与状态机重构同步解决

**现象**: 点情绪按钮后模型瞬间跳到目标姿势，没有过渡过程。

**根因**: `setEmotion` 直接把 30 个参数写进 `_emotionParams`，idleLoop 下一帧直接送到 `setParams`——零过渡。

**修复 — 动画插值**:

```javascript
let _animTarget = null;      // 目标参数
let _animStart = null;       // 起点快照
let _animStartTime = 0;
const ANIM_DURATION = 400;   // 400ms 过渡

function setEmotion(name) {
  _animStart = { ..._emotionParams };  // 当前值快照
  _animTarget = target;                // 目标值
  _animStartTime = performance.now();
}

function idleLoop() {
  if (_animTarget) {
    const t = ease((now - _animStartTime) / ANIM_DURATION);
    for (const [key, to] of Object.entries(_animTarget)) {
      _emotionParams[key] = (_animStart[key] ?? 0) + (to - (_animStart[key] ?? 0)) * t;
    }
  }
  // ... 合并呼吸 + 动作 → po.setParams(merged)
}
```

**教训**: 情绪 = 动画，不是瞬时切换。起点快照 + 目标 + ease-in-out 函数，每个参数独立插值。动画完成前呼吸/动作照常叠加。

## 坑 7: EPSILON 太小 + token 簇含高频词 → 情绪"触之即炸"

> 2026-06-10 | 调试耗时 ~1h

**现象**: 聊天时几乎永远触发"惊讶"（surprise），蚊香眼频繁出现。

**调试过程**:
1. 写 `debug_probe.py` 直接测 Ollama 的 logprobs 前 20 token
2. 发现中性 prompt "描述你现在的情绪:" 下，惊讶/好奇/困惑三簇基线概率为零（0.0%）
3. 原 `EPSILON=0.005`，任何 token 命中率 > 0.5% 就触发
4. 惊讶簇含高频词"什么"（Top 20 常驻），频繁命中 → 律度虚高

**修复**:
- `EPSILON` 从 0.005 提到 0.02（需 4× 刺激才触发）
- 清掉所有日常高频词（"什么""怎么""为什么""看看"等）
- 基于实测数据补充漏词（快乐 + "兴奋""愉快"）

**教训**: token 簇设计不能凭感觉，需要跑 logprobs 实测看模型真正预测什么词。零基线簇必须有大 EPSILON 保护。

## 坑 8: 两条情绪推送线打架 → 一直 surprise

> 2026-06-12 | 调试耗时 ~1h

**现象**: 不管怎么调 logprobs 参数，前端 Live2D 始终显示 surprise。

**根因**: 存在两套情绪推送系统：

```
线1 (旧): LLM 内联标签
  prompt 写着 "回复前用 [emotion:xxx] 标记表情"
  → LLM 回复 "[emotion:surprise] 哇..."
  → chat_stream 实时解析 → SSE 推送 → 前端切惊喜

线2 (新): logprobs 测量
  → detector.measure() → get_top_emotion() → WebSocket 推送
```

线1 推送最早最快，LLM 偏爱输出 `[emotion:surprise]`，线2 的结果永远被覆盖。

**修复**:
- 删除 prompt 中的 "回复前用 [emotion:xxx] 标记表情" 指令
- 删除 chat_stream 中的内联标签实时提取和 SSE 推送
- 情绪改为单一来源：logprobs 测量 → `get_top_emotion()`

**教训**: "麦克风插到显卡上"——两套系统看似独立，实际上输出端打架。删旧推新时要把旧管道的所有输出端全掐掉。

## 坑 9: 情绪命名统一 → EMOTION_CYCLES 8族丢失 → 开心循环假破

> 2026-08-05 | puppet_live2d_v2.html

**背景**: 8族"族名即 v1"(sad/angry/fear/confused/hurt/amused/excited/approach)改为"容器+_v1"命名。

**现象**: 开心循环"坏了"——VAD进开心后永远停在 happy_v1。

**调试**: 加了 [SET] 日志发现 src=CYC 正常切变体——循环其实一直在跑。[CONTEMPT] 日志(每次 setEmotion 都触发 stopContemptCycle)刷屏误判为"循环被停"。

**根因**: EMOTION_CYCLES 缺失 sad/angry/fear 等 8 族入口, 但开心等原有 8 族从未丢失——是 [CONTEMPT] 噪音误导。

**教训**: 日志噪音和实际 bug 容易混淆。看 src=CYC 就知道循环在跑, 不应该被 stopContemptCycle 带偏。

## 坑 10: 轻蔑状态机抄了 6 次才抄对

> 2026-08-05 | 耗时 ~2h | 自回归模型的"理解"是负资产

**任务**: 做一个"转头"按钮, 效果跟轻蔑v1一模一样。

**失败的尝试**(5次):
1. phases 走弹簧(眼珠过渡 0.5s vs 状态机 0ms)
2. phases 加 k=500 弹簧(快但仍有过渡)
3. phases 改用 override 字段(加了"结尾回正"擅自改设计)
4. phases 加 blink120ms 过渡(加了随机概率被拒)
5. 调用 setEmotion('contempt_v1')(用户要独立副本)

**正确做法**(第6次, 3分钟): 完整复制状态机代码 → 变量名加 `_emote` 前缀 → 完成。一行逻辑没改, 一个数值没调。

**教训**: "一模一样"的意思就是一模一样。自回归模型在复制粘贴类任务上的"理解"和"改进"完全是负资产——每次自我发挥都引入新错误, 每修正一个又制造一个, 6 次循环无一例外。
