# 长期记忆 — 架构说明

> 最后更新: 2026-08-02
> 状态: ✅ 全链路跑通（L0 → L0.5 → BERT分类 → 重心位移 → 只走主移动一步 → 标签过滤 → embedding 精排 → 命中）
> 数据: 1489 条（2026-08-01 重导）+ BERT 重训完成（2026-08-01）

---

## 概述

模拟人类长期记忆的主动检索机制。每一轮对话（L0）在 LLM 回复完成后**立即**处理成第一视角转写（L0.5），走"分类 → 重心位移 → 只走主移动一步 → 标签过滤 → embedding 精排"的检索 pipeline，命中记忆库中与该轮对话最相关的历史记忆。

与上文记忆（L0→L1→L2→L3→L4 压缩归档）的区别：

| | 上文记忆 | 长期记忆检索 |
|--|---------|------------|
| 触发时机 | history > 10 条（第6轮）批量处理最老一轮 | 每轮 LLM 回复完成后立即处理最新一轮 |
| 方向 | 写入（压缩归档） | 读取（召回相关记忆） |
| 输出 | L1~L4 摘要 | 检索命中的历史条目 |
| 依赖 | 摘要模型 4B (18773) | 检索服务 (18774) |

## 数据流

```
LLM 回复完成 → history 追加
  ↓
trigger_retrieval()  [pipeline_server.py]
  1. 取最新一轮 (user_raw + reply_full)
  2. build_l05()：parse_reply 拆 想法/回复/工具 → 动作描述
     → 拼成 L0.5: "{来源}对我说：xxx\n我想：xxx\n我说：xxx"
  3. 【本地】先填充 last_retrieval 的 l0 / l05（不依赖服务）
  4. POST http://localhost:18774/retrieve {user, thought, action}
  ↓
memory_retrieve_server.py (18774)
  1. full_text = user + coin_text（硬币 = thought + action）
  2. BERT 分类 full_text → 全量标签（领域/规模/时间/评价 各概率分布）
  3. BERT 分类 coin_text → 硬币标签
  4. 重心位移 Δ = 硬币重心 - 全量重心（评价/规模/时间三轴）
     ※ 时间/规模轴 ×0.5 衰减（分类易波动），评价轴保持全量（真正的态度信号）
  5. 主移动 = |Δ| 最大的轴（|Δ|<0.05 视为无移动）
  6. 【只走主移动一步】只有主移动轴偏移一级，其他轴保持全量分类
     → 目标检索空间（例：社交/关系 + 普通 + 现在 + 我喜欢）
  7. SQLite 标签过滤（严格→宽松 4 级降级）
  8. bge embedding 余弦 → top-3 候选
  ↓
返回 4 块 JSON → pipeline_server 存 last_retrieval
  ↓
页面 🔍 检索记忆 tab：① L0 ② L0.5 ③ 标签计算 ④ 检索命中
```

## 关键设计决策

1. **独立进程**：检索服务（18774）独立于主管线——BERT+bge 加载慢（几十秒）不拖累主管线启动；可单独重启调试。
2. **L0/L0.5 本地即时生成**：`trigger_retrieval` 先用 `build_l05` 本地拼好并填充，再调检索服务。服务挂了前两块照常显示。
3. **每轮实时处理**：不等待 batch，LLM 回复完成立刻处理最新一轮。
4. **重心位移衰减**：时间/规模轴 ×0.5（分类易波动、易把检索空间带偏），评价轴保持全量——评价是"硬币态度"的核心信号。
5. **只走主移动一步**：只有 |Δ| 最大的轴偏移一级，其他轴保持全量分类。避免多轴同时走导致目标空间跳到无数据的组合（如"中等+过去"过滤掉感情线）。
6. **主移动阈值**：|Δ| < 0.05 视为无显著移动。
7. **防重复导入**：UNIQUE(text, domain) + INSERT OR IGNORE，重跑导入自动跳过已有条目。
8. **线程安全**：check_same_thread=False（HTTP 请求在子线程访问）。
