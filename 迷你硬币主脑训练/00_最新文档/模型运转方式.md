## 二、模型调用方式（推理时）

### 标准对话流程

```
用户输入
  ↓
模型接收 System Prompt + 用户消息
  ↓
模型生成：
  1. 分析对方意图（用中文思考）
  2. 决定要做什么
  3. 调用工具：[TOOL:回复/搜索/表情/报错] 内容 [TOOL]
  ↓
如果是 [TOOL:结束] → 本轮结束，等用户下一句
如果是 [TOOL:回复/表情/搜索] → 等待外部注入
  ↓
外部注入内容（例如搜索结果、空内容等）
  ↓
模型继续分析 + 调用下一个工具
（可多次循环）
  ↓
直到模型输出 [TOOL:结束] [TOOL]
```

### 工具列表

| 工具 | 格式 | 用途 |
|------|------|------|
| 回复 | `[TOOL:回复] 说话内容 [TOOL]` | 直接对用户说话 |
| 搜索 | `[TOOL:搜索] 关键词 [TOOL]` | 搜索互联网（等待注入搜索结果） |
| 表情 | `[TOOL:表情] 表情名 [TOOL]` | 做表情动作：认真/wink/开心/spin/转头/担心 |
| 报错 | `[TOOL:报错] 信息 [TOOL]` | 工具出错时调用 |
| 结束 | `[TOOL:结束] [TOOL]` | 本轮结束，等对方回应 |

## 七、推理时 LogitsProcessor 修正

### 7.1 TOOK 混淆修正

- **现象：** 模型在 `[`(58) + `TO`(5207) 后偶发选 `OK`(3925) 而非 `OL`(1930)，生成 `[TOOK` 而非 `[TOOL`，随后陷入复读循环。
- **根因：** BPE tokenizer 中 `TOOL=TO(5207)+OL(1930)`，`TOOK=TO(5207)+OK(3925)`。`OL` 和 `OK` 在 embedding 空间距离过近，采样时偶尔选错。UL 惩罚 `OK` 会误伤正常分布，不可行。
- **方案：** 推理时 LogitsProcessor 干预：

```python
class ToolBiasProcessor(LogitsProcessor):
    def __call__(self, input_ids, scores):
        if input_ids.shape[-1] >= 2:
            if input_ids[0, -2].item() == 58 and input_ids[0, -1].item() == 5207:
                scores[:, 1930] += 100.0   # OL ↑
                scores[:, 3925] -= 100.0   # OK ↓
        return scores
```

- **注入点：** `model.generate(logits_processor=LogitsProcessorList([ToolBiasProcessor()]))`

### 7.2 表情后 EOS 拉升（软规则，贴入即生效）

- **现象：** 命令类 golden（如"笑一个"）的 output 不含 `[TOOL:结束]`，模型偶尔在 `[TOOL:表情]xxx[TOOL]` 后继续输出下一个工具而非 EOS。
- **注意：** `[TOOL:搜索]` 后不应 EOS（要先等搜索结果），所以只对 `[TOOL:表情]` 生效。
- **方案：** 检测到 `[TOOL:` + `表情` 的闭环 `]` 后，下个 token 推高 EOS +50：

```python
class EmoteEOSProcessor(LogitsProcessor):
    EOS_ID = 151643
    EMOTE_ID = 102936
    def __call__(self, input_ids, scores):
        n = input_ids.shape[-1]
        if n < 7: return scores
        if input_ids[0, -4:].tolist() != [58, 5207, 1930, 60]:
            return scores
        for i in range(n-5, max(0, n-30), -1):
            if input_ids[0, i:i+4].tolist() == [58, 5207, 1930, 25]:
                if input_ids[0, i+4].item() == self.EMOTE_ID:
                    scores[:, self.EOS_ID] += 50.0
                break
        return scores
```

### 7.3 结束 tool 后强制 EOS（软规则，贴入即生效）

- **现象：** 模型在 `[TOOL:结束] [TOOL]` 后偶发继续生成无意义内容。
- **方案：** 检测到 `[TOOL:结束] [TOOL]` 闭环后，EOS 强制拉升到几乎必然选中：

```python
class EndEOSProcessor(LogitsProcessor):
    EOS_ID = 151643
    END_TOKEN = 80565  # 结束
    def __call__(self, input_ids, scores):
        n = input_ids.shape[-1]
        if n < 7: return scores
        if input_ids[0, -4:].tolist() != [58, 5207, 1930, 60]:
            return scores
        for i in range(n-5, max(0, n-30), -1):
            if input_ids[0, i:i+4].tolist() == [58, 5207, 1930, 25]:
                if input_ids[0, i+4].item() == self.END_TOKEN:
                    scores[:, self.EOS_ID] += 100.0  # EOS 几乎必选
                break
        return scores
```

### 7.4 统一注入

三个 Processor 一起使用：

```python
model.generate(
    ...,
    logits_processor=LogitsProcessorList([
        ToolBiasProcessor(),
        EmoteEOSProcessor(),
        EndEOSProcessor(),
    ])
)
```

不改变模型权重，贴入推理代码即生效。

### 禁止思考模式（Thinking Mode）

**正确做法（参考 `agent_test_manual.py` 和 `grpo_tool_main_v3a.py`）：**

```python
# 1. 构造 prompt 时必须加 enable_thinking=False
prompt = tokenizer.apply_chat_template(
    messages, tokenize=False, add_generation_prompt=True,
    enable_thinking=False     # ← 关键：阻止 Qwen3 在 prompt 末尾插入 <think>
)

# 2. 训练脚本额外做的事情（推理时如果不放心也可以加上）：
if hasattr(tokenizer, 'thinking_mode'):
    tokenizer.thinking_mode = False
if hasattr(model, 'generation_config') and hasattr(model.generation_config, 'enable_thinking'):
    model.generation_config.enable_thinking = False
```

`enable_thinking=False` 必须传进 `apply_chat_template`，单独设置 tokenizer 属性不一定生效。测试脚本 `agent_test_manual.py` 用的是手动逐 token 生成 + `enable_thinking=False` 的方式，这是正确的推理模式。

### Loss 结构

- **GRPO 主 loss**：golden 续写 ×20，采样续写 ×0.01
- **UL（Unlikelihood）**：采样续写出现复读时，对复读 token 做 `-log(1-p)` ×40
  - 三种检测：尾巴复读、前向复读、6x 任意重复
- **反向 UL**：已移除（模型已学会自动生成 EOS）
