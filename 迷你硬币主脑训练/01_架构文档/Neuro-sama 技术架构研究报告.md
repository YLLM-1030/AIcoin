# Neuro-sama 技术架构研究报告

> 研究时间：2026-06-16
> 研究目的：弄清 Vedal 如何让一个小模型实现直播中的社交互动能力，为 miniCoin 的改进提供参考

---

## 一、系统全景：不是单个模型，是一套流水线

Neuro-sama 不是一个 LLM + 一个 TTS 那么简单。Vedal 搭建了一套**分层流水线**，每个层次各司其职：

```
输入层                   认知层                    执行层
━━━━━━━                ━━━━━━━                 ━━━━━━━
Twitch 弹幕  ──────┐
                   ├──→ 微调 LLM (~2B?) ──→ 对话文本 ──→ TTS(微软Azure) ──→ Live2D 口型
语音输入 → STT ────┘                     │
                                         └──→ 动作指令 ──→ Neuro API(WebSocket)
                                                             │
                                                    ┌────────┼────────┐
                                                    ▼        ▼        ▼
                                              游戏集成层 游戏集成层 游戏集成层
                                              (osu!)   (Minecraft) (Among Us)
```

**关键要点**：Vedal 把"对话"和"玩游戏"拆成了两条完全独立的流水线。LLM 只负责对话 + 生成高层意图，具体执行交给专门的控制器。

---

## 二、模型：到底多大？—— 未知

### 已知事实
- Vedal **从未公开参数量**。社区传 2B q2_k，但**没有一手来源**。
- 唯一能确定的是：**不是 GPT-4/Claude 级别的模型**，能在消费级显卡上本地跑。
- 基座模型未公开，社区猜测 LLaMA 系。

### 为什么猜这么小
- **延迟要求**：直播需要 1-3 秒内回复，大模型做不到。
- **成本**：Vedal 自托管，没有云 API 费用。

### 重要推论
**如果 2B 为真，那么 Neuro 的行为几乎全部来自微调数据的质量，而非模型容量。** 同时需要在极度激进的量化（q2_k）下维持人格——这要求训练数据必须极其精炼。

## 三、训练数据：核心机密

Vedal 公开说过的最有价值的信息：

### 数据来源
- **Vedal 与 Neuro 的互动日志** — 他亲自与 Neuro 对话的记录
- **直播弹幕精选** — 从 Twitch 聊天中筛选的高质量互动
- **Vedal 手动编写** — 部分高质量对话示例是他自己写的

### 数据格式
推测为对话对格式：
```
用户输入 → Neuro 回复

用户: "Hello Neuro"
Neuro: "Hi! How's your day going?"

用户: "Play osu!"
Neuro: "I don't feel like it right now."
```

### 关键特征
- **不是指令微调格式**（instruction → response），而是**自然对话格式**
- **包含 Vedal 的评分** — 他对每条回复打分，"这个回答好/不好"
- **风格优先于正确性** — 训练目标是"像 Neuro 会说的话"，而非"正确的回答"

### 持续积累
- 每次直播都是数据收集过程
- Vedal 人工审核 → 精选 → 加入训练集
- **关键瓶颈是人的参与**，不是技术

## 四、微调方案：SFT + 轻量 RLHF

### 第一步：监督微调 (SFT)
在精选对话对上训练 base model，学会 Neuro 的说话风格。人格被直接"烤"进权重。

### 第二步：轻量 RLHF
Vedal 在后**台对 Neuro 的每条回复打分**（直播中他说过"I just gave that response a low score"）。

流程：
```
Neuro 回复 → Vedal 打分(1-10) → 收集评分数据 → 微调优化
```

这不是标准 RLHF（没有独立的 reward model），而是一种**人在回路的在线强化**。

### 人格切换（Neuro vs Evil Neuro）
两种可能：
1. **LoRA 切换** — 不同的 LoRA 权重对应不同人格
2. **prompt 切换** — 相同权重，不同 system prompt

如果是 LoRA 切换，意味着生产中实现了"按角色提供适配器"的服务模式。

## 五、弹幕处理：最关键的部分

这里可能是 miniCoin 差距最大的地方。

### Neuro 的弹幕管道
```
Twitch 弹幕流
    ↓
弹幕过滤 (去重/垃圾/刷屏)
    ↓
弹幕采样 (每 5-30 秒选 1-5 条高价值弹幕)
    ↓
格式化注入 Prompt: [Chatter: 用户名] 消息内容
    ↓
LLM 处理
```

### 与 miniCoin 的对比

| 环节 | Neuro | miniCoin |
|------|-------|----------|
| **过滤** | 有专门的过滤模块 | 没有，所有弹幕直接进 |
| **采样** | **只选高价值弹幕**，不是全量 | 全部弹幕堆进去 |
| **频率** | 5-30s 采样一次 | 每次对话才注入 |
| **结构化** | `[Chatter: 用户名]` 带身份 | 只有文本 |
| **优先级** | SC/舰长 > 活跃用户 > 普通 | 没有优先级 |

**关键洞察：Neuro 不处理所有弹幕。她选着回。** 这大大降低了 LLM 的上下文噪音。

### 关于"认人"
- **没有真正的跨会话用户识别**
- 认识 = 当前 session 里某个用户名出现过几次
- 模型根据训练数据里学到的模式匹配回应
- **关播后记忆清空**

## 六、分层动作架构（最精妙的部分）

Vedal 公开的 GitHub 仓库揭示了核心设计模式。

### 三层结构

```
第一层：LLM（人格层）
  输入：文本化游戏状态 + 弹幕 + 历史
  输出：结构化动作指令 (如 "play_card: {id:3, lane:2}")
  
第二层：Neuro API（动作总线）
  协议：WebSocket
  核心原语: Context, Registered actions, Forced actions
  功能：约束 LLM 输出在合法范围内
  
第三层：游戏集成层（执行层）
  例如:
    neuro-inscryption → NeuroMouse 执行鼠标点击
    neuro-amongus → 独立 LSTM 模型做寻路导航
    neuro-cyberpunk → 调用游戏原生 Redscript 方法
```

### 实例：玩《Among Us》
1. LLM 生成高层意图："去反应堆做任务"
2. Neuro API 将意图传给 `neuro-amongus` 集成层
3. 集成层内有一个**独立的 LSTM 模型**，负责低层移动策略和避障
4. LSTM 配合路径求解器，具体执行鼠标/键盘操作

**LLM 从不直接生成鼠标点击坐标。** 它只生成"意图"，执行交给专门的小模型/算法。

## 七、记忆系统：比你想象的弱

### 确认存在的
- **会话内上下文** — 当前直播 session 内的对话历史
- **Vedal 后台记录的笔记** — 以结构化文本存储的事实

### 可能存在的
- **向量检索**（类似 RAG）— 有迹象但未证实

### 不存在的
- **跨会话持久用户记忆**

### 关键发现
Neuro 的"记忆"比 miniCoin 的向量库弱。miniCoin 有完整的向量存储 + 检索 + 注入链路，反而比 Neuro 强。问题不在记忆系统，在**如何用记忆**。

## 八、持续学习管线

```
直播（纯推理，不更新权重）
    ↓
收集对话转录文本
    ↓
Vedal 手动筛选（人工瓶颈）
    ↓
离线微调（全量或 LoRA）
    ↓
部署新模型
    ↓
循环
```

### 特点
- **不是在线学习** — 直播中权重不动
- **迭代批量微调** — 隔一段时间集中训一次
- **人在回路** — 数据筛选完全靠人
- **灾难性遗忘是已知问题** — Vedal 如何处理未公开

## 九、与 miniCoin 的对比总结

| 维度 | Neuro-sama | miniCoin |
|------|-----------|----------|
| **模型大小** | 推测 ~2B | 8B q8_0 |
| **人格来源** | 微调进权重 + prompt 辅助 | 微调进权重 |
| **训练数据** | 精选对话对 + 人工评分 | 216 条硬件/代码指令 |
| **数据多样性** | 覆盖日常对话 | 集中在硬件/代码 |
| **弹幕处理** | 过滤 + 采样 + 优先级 | 全量直接注入 |
| **分层架构** | ✅ LLM 只做意图 | ❌ LLM 什么都干 |
| **记忆系统** | 会话内 + 笔记文件 | 向量库 + 关键词检索 |
| **跨会话记忆** | ❌ 没有 | ✅ 有（但数据为空） |
| **多模态** | 独立视觉模型 + 独立游戏控制器 | 视觉正在修 |
| **RLHF** | 轻量级人在回路 | 没有 |

### miniCoin 的差距不在模型大小，在三个点

**差距 1：训练数据质量 >> 训练数据数量**
- Neuro 的 2B（如果为真）靠精选数据撑起人格
- miniCoin 的 8B 被 216 条同质数据过拟合
- **结论：不解决数据问题，换更大的模型也没用**

**差距 2：弹幕管道——过滤和采样**
- Neuro 选弹幕回，不是全量回
- 过滤噪音 + 降低 LLM 上下文负担
- **结论：miniCoin 需要弹幕优先级和采样机制**

**差距 3：分层架构**
- Neuro 的 LLM 只负责任意 + 对话
- 执行交给专门的小模型/控制器
- **结论：miniCoin 的 LLM 负担太重，什么都要做**

## 十、对 miniCoin 的实际建议

### 优先级 1：修训练数据（根本问题）
- 改人称：b1.0/1.5/2.0 所有"他(拉姆)"→"你"
- 扩场景：加日常对话、弹幕互动、通用话题
- 加多样性：参考 Neuro 的方法，混入自然对话数据
- 数量：从 216 → 400+ 条

### 优先级 2：弹幕管道改造
- 加弹幕优先级（SC > 舰长 > 活跃 > 普通）
- 加弹幕采样（每次只选 top 3-5 条，不是全量）
- 加文本过滤（去重/刷屏/广告）

### 优先级 3：分层架构（长期）
- 把"游戏操作/工具调用"从 LLM 中拆出来
- LLM 只负责对话 + 生成意图
- 专门的控制器执行具体操作

---

*报告完毕。核心一句话：Vedal 用 2B 做好的事，miniCoin 的 8B 完全有潜力做得更好——前提是解决训练数据过拟合的问题。*
