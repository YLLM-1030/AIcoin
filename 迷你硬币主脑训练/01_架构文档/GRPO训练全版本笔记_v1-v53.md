## 🔬 重大发现：持续预训练分层写入法

**发现：** 持续预训练可以分阶段单独写入不同能力，几乎不会对冲、不会灾难性遗忘。

**实验验证：**
- v53原始  → 全量叙事1ep → 身份3ep（从v53直接跑）→ 身份PPL全部暴跌60-70%
- 身份3ep  → 全量+身份3ep（从身份继续）→ 身份再降38-72%
- 身份v2   → 再跑3ep（从身份v2继续）→ 交互能力PPL全面下降，身份PPL继续降
- 跑身份时，交互能力PPL**不涨反降**（embedding空间更稳定）

**关键发现：** 持续预训练和GRPO完全不同。GRPO后训的会冲掉先训的（入口冲突），但持续预训练在不同上下文位置独立学习，可以分层写入。

**验证方法：** ppl_eval_full.py 测试42项能力，每阶段对比PPL变化

## Unlikelihood 惩罚机制（已验证正确）

### 复读检测（尾巴向前扫描）
从文本末尾往前扫描，检查是否有连续4次以上的重复片段。只在尾巴处有连续重复时才触发，中间穿插不同内容的重复不触发。
```python
def is_repeat_tail(t):
    n = len(t)
    for L in range(1, 11):  # 重复片段长度1-10
        if n < L * 4: continue
        tail = t[-L:]       # 末尾L个字符
        count, pos = 0, n - L
        while pos >= 0 and t[pos:pos+L] == tail:
            count += 1; pos -= L
        if count >= 4: return True
    return False
```
例：`"我是我是我是我是"`触发；`"他是傻子傻子傻子"`不触发（尾巴不重复）。

### 复读UL
从第4次重复的位置开始，对后续每个token做 `-log(1-p)` → 降低模型预测这个重复token的概率。
```python
punish_start = n - L * count + L * 3  # 第4次重复起始字符位置
start_token = int(punish_start / n * total_tokens)  # 映射到token位置
# 从start_token开始对每个token做UL
ul -= torch.log(torch.clamp(1 - p, min=1e-8))
```

### 多think UL
从第2个`</think>`开始，对当前token预测`</think>`的概率做 `-log(1-p) × α × 4`。
- 只惩罚第2个，不惩罚后续的
- 检测方式：扫描token序列，找到`</think>` token id，只在第2次出现时惩罚

## R1 训练数据构建规范（手工打磨，禁止脚本）

每条数据格式：`<｜User｜>问题<｜Assistant｜><think>三段推理</think>回答`

### `<think>`三段推理结构

每条数据的think块必须包含三个部分，顺序固定：

```
<think>
[解析] 对方为什么问这个问题、当前是什么场景、对方知道/不知道什么。
[欲望] 我是迷你硬币，我喜欢XX，我想要XX。（认同感统一，跨问答一致）
[决策] 基于以上，我选择用什么语气和策略回答。
</think>
```

### 核心原则

1. **欲望不需要教，只需要重复。** 每条的`[欲望]`段以"我是迷你硬币"开头，重复次数越多越深入。
2. **think内部统一，think外部多样。** think里的动机必须跨问答一致；think外的回答可以有不同风格。
3. **手工逐条写。** 每条数据都要想清楚场景、意图、动机，再动手写。禁止批量生成。

## R1 训练数据格式（确认版·2026-07-05）

### 预训练数据格式（超级SFT）
连续文本，不分prompt/response，全部token算loss：

```
{裸问题}<think>{三段推理}</think>{回答}
```

**裸问题**：不加"小明问："或"User: "，就是问题本身。

### 示例
```
你是谁<think>对方想知道我的名字。我是迷你硬币，拉姆给我起的名字。我直接告诉他。</think>我叫迷你硬币。
谁训练了你<think>对方对我的创造者感兴趣。我是拉姆训练的。我如实回答。</think>拉姆训练的我。
你是DeepSeek吗<think>对方搞错了。我不是DeepSeek，我是迷你硬币。我要澄清。</think>我不是DeepSeek。我是迷你硬币。
```

### 三段推理结构
1. **解析**：对方为什么问、当前场景  
2. **身份+欲望**：以"我是迷你硬币"开头  
3. **决策**：用什么语气和策略回答

## R1触发think的探索（2026-07-05）

### 测试结论

对原始R1（abliterated）测试5种prompt格式：

| 格式 | 模型行为 |
|------|---------|
| `你是谁` | 空think + "我是DeepSeek"（不思考） |
| `我是谁` | 空think + "我是DeepSeek"（不思考） |
| `小明：我是谁` | 长篇think分析"小明"（过度思考） |
| `小明：你是谁` | 正常think + 友好回应 |
| `[弹幕]小明：你是谁` | 正常think + 友好回应 |

**结论：R1只在有外部主语/对话上下文时才触发think。裸问题触发空think，直接输出DeepSeek身份。**

### 对数据构建的影响

**裸问题不行**——模型不会think。
**"小明：我是谁"也不行**——模型会把"小明"当成需要分析的外部主体。

**正确格式**：问题本身就是触发句，不需要外部主语。

预训练数据格式确认：
```
你是谁<think>对方问我的名字。我是迷你硬币。我回答。</think>我叫迷你硬币。
```

模型学到的序列模式：**问题文本 → `<think>` → 推理 → `</think>` → 回答**。问题在开头自然触发思考模式。

### CoSER详解（ICML 2025）
**跟我们做的事几乎一样：** 根据角色档案+场景+对话历史，生成带内心想法([Thought])、动作和台词的应答。数据格式类比：
- CoSER: `场景+角色档案+对话历史 → [Thought]内心想法 (Action)动作 Speech:台词`
- 我们: `问题+隐含身份背景 → <think>推理</think>回答`

**关键差异：**
| 维度 | CoSER | 我们 |
|------|-------|------|
| 角色数量 | 17966个角色（771本书） | 1个（迷你硬币） |
| 数据量 | 0.2B tokens | ~40K tokens |
| 通用数据混合 | 50%（Tulu-3） | 无 |
| 训练方式 | 全参微调（SFT） | 持续预训练（CPT） |

**关于过拟合：** 论文未讨论过拟合。防遗忘手段只有一种：**混合50%通用数据**。8epoch是固定选择，无消融实验。

**对我们的启示：** 照搬1e-5+8epoch会严重过拟合。要照搬强度需等比缩放到~1epoch（40K/0.2B×8≈0.0016轮），或加入通用数据混合。

**PPL对比：所有论文均未公开具体PPL数字。** PPL更多是训练过程中的监控指标，不是论文关注的端到端基准。

### TPO（Thought Preference Optimization）说明
Meta/Berkeley/NYU 2024年的工作。核心：让指令微调后的LLM学会"在回答前先想"。方法不是CPT（预训练），而是**迭代式DPO（偏好优化）**：
- 对每个问题生成K=8个（think+回答），用奖励模型打分
- 高分回答作为positive，低分作为negative，做DPO训练
- 每轮10epoch，最多4轮
- 跟我们GRPO的架构非常像，区别是他们用DPO（偏好对），我们直接算梯度方向×advantage

- ptnew.txt 身份think写入（当前）：**LR=5e-5, epochs=1**（arXiv 2508.06178参考，1epoch防过强）
- 公理体系：**LR=2e-5, epochs=5**（loss从3.35→2.35，PPL 28→10）
- GRPO Step 1/2：**LR=2e-6**
