## 核心设计：LoRA热插拔

```
每个LoRA = 一个独立的能力文件（10-50MB）

```

## 推理时LoRA热插拔流程

```
输入: "拉姆把我的TNT全没收了！"

Step 1: 加载场景LoRA（0.1秒）
  load_lora("场景_游戏MC")
  → 模型知道：我在MC世界，有TNT有工具

Step 2: Router判断意图
  输入检测到"拉姆"+"没收"+"愤怒"
  → 选择意图LoRA_惩罚

Step 3: 合并意图LoRA（0.1秒，权重相加）
  merge_lora("意图_惩罚")
  → 模型同时知道"场景=MC"+"意图=惩罚"

Step 4: 生成回复
  "我把你家也炸了！公平公正！"

Step 5: 下次交互只换意图LoRA
  输入"你好可爱啊" → Router选"撒娇"
  swap_intent_lora("撒娇")  # 场景不动
  → "嘿嘿谢谢~你们也很可爱！"
```

## Qwen3 Thinking 模式控制（2026-07-11 验证）

enable_thinking=False 必须在 `tokenizer.apply_chat_template()` 中设置才生效。
字符串拼接注入 `<think>\n\n</think>\n\n` 无效——必须走 apply_chat_template。
原理：`apply_chat_template(enable_thinking=False)` 会在 assistant 后精确注入
`<think>\n\n</think>\n\n`，使用正确的 token ID 序列，模型才会认。
验证：逐 token 生成 + `apply_chat_template(enable_thinking=False)` 可同时实现
think 抑制和实时截断。

## 反向UL（2026-07-11 发明）

原理：和 UL 相反，不是压低错误 token 概率，而是拉高正确 token 的概率。
公式：`-torch.log(clamp(p, min=1e-8))` → 模型越确信，值越大。

当前应用的两个场景：

1) [TOOL:结束] → 后面全部喜欢
   检测到 [TOOL:结束] 后，之后的所有 token（ [/TOOL]<|endoftext|>）一起拉高概率
   倍率：10.0
   作用：教会模型 "结束之后就是 EOS，不要继续生成"

2) [TOOL:搜索] → [搜索结果：
   检测到 [TOOL:搜索] [/TOOL] 后有 [搜索结果：，拉高这段 token 概率
   倍率：10.0（和上面共用同一个 loss 累加器）
   作用：教会模型 "搜索完就会有结果回来"

代码结构（grpo_tool_main_v2.py）:
    ga = gi["input_ids"][0][prompt_len:]
    liked = 0.0; lcnt = 0
    # 找到 [TOOL:结束] → 后面全喜欢
    # 找到 [TOOL:搜索] → 找到 [/TOOL] 后的 [搜索结果： → 喜欢
    if lcnt > 0:
        liked = liked / lcnt * 10.0
        liked.backward()
```

## 推理测试代码（已验证）

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

MODEL_PATH = "/mnt/c/Users/Autogram-coin/Desktop/ckpt_tool_main_v2"
MAX_NEW = 500

model = AutoModelForCausalLM.from_pretrained(MODEL_PATH, torch_dtype=torch.bfloat16,
    trust_remote_code=True, device_map="auto", local_files_only=True)
tokenizer = AutoTokenizer.from_pretrained(MODEL_PATH, trust_remote_code=True, local_files_only=True)
tokenizer.pad_token = tokenizer.eos_token
model.eval()

TOOL_SYS = """你是迷你硬币，拉姆是你的创造者。
你可以使用工具。
[TOOL:回复] 内容 [/TOOL] — 回复用户
[TOOL:搜索] 关键词 [/TOOL] — 搜索互联网
[TOOL:表情] 情绪 [/TOOL] — 情绪动作：认真/wink/开心/spin/转头/担心
[TOOL:报错] 信息 [/TOOL] — 工具出错时调用
[TOOL:结束] [/TOOL] — 本轮结束"""

def detect_stop(t):
    if "[TOOL:结束][/TOOL]" in t or "[TOOL:结束] [/TOOL]" in t: return "end"
    if "[/TOOL]" in t: return "tool"
    return None

def run(user_input):
    msgs = [{"role": "system", "content": TOOL_SYS}, {"role": "user", "content": user_input}]
    prompt = tokenizer.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True, enable_thinking=False)
    inp = tokenizer(prompt, return_tensors="pt").to(model.device)
    plen = inp.input_ids.shape[1]
    ids = inp.input_ids.clone()
    for _ in range(MAX_NEW):
        with torch.no_grad():
            out = model(ids)
        tok = torch.argmax(out.logits[0, -1, :]).unsqueeze(0).unsqueeze(0)
        ids = torch.cat([ids, tok], dim=-1)
        t = tokenizer.decode(ids[0, plen:], skip_special_tokens=True)
        s = detect_stop(t)
        if s: return t, s
        if tok.item() == tokenizer.eos_token_id: return t, "eos"
    return tokenizer.decode(ids[0, plen:], skip_special_tokens=True), "maxlen"
```

关键点：
- 必须用 `apply_chat_template(..., enable_thinking=False)` 抑制 think
- 不能用纯字符串拼接（否则模型会输出 `<think>`）
- 逐 token 生成 + detect_stop 实现实时截断
- TOOL_SYS 里必须用 `[/TOOL]`（与训练数据一致）

## Agent 输入路由规则

推理时的输入路由：

```
新对话首轮:
  prompt = apply_chat_template(sys_msg, user_msg)
         = <|im_start|>system\n...<|im_end|>\n<|im_start|>user\n输入<|im_end|>\n<|im_start|>assistant\n

工具截断后注入:
  prompt = 已有上下文 + 注入文本 + "\n"
  （直接追加到当前 assistant 消息末尾，不开新 user 消息）

[TOOL:结束] 后:
  下一轮输入走新的 <|im_start|>user\n
```

def generate(ctx):

ctx = ""
in_round = False

while True:
    inp = input(">>> ").strip()
    if inp == "/end": break
    if inp == "/new":
        ctx = ""; in_round = False; print("重置"); continue
    if not in_round:
        msg = [{"role": "system", "content": TOOL_SYS}, {"role": "user", "content": inp}]
        ctx = tokenizer.apply_chat_template(msg, tokenize=False, add_generation_prompt=True, enable_thinking=False)

    t, s = generate(ctx)
    print(t, "[%s]" % s)
    if s == "end":

## 当前状态与待解决问题

**已正常工作的部分：**
- 工具调用截断 ✅  `[TOOL]` 精确匹配
- think 抑制 ✅ `apply_chat_template(enable_thinking=False)`
- 注入路由 ✅ 工具截断后注入到 assistant 末尾
- 无 `<think>` 输出 ✅

**待解决的 2 个问题：**

1. **表情提示不够清晰** — 模型会输出 `[TOOL:转头]` 而不是 `[TOOL:表情] 转头 [TOOL]`。需要修改 TOOL_SYS 里的表情说明，让模型明确知道要用 `[TOOL:表情]` + 表情名称。

2. **模型不会主动用 `[TOOL:结束]`** — 注入后模型倾向于继续生成工具调用，不会主动输出结束。需要修改结束相关的提示词，让模型知道什么时候该结束。

## 心理分析注入方案（2026-07-12）

**问题**：模型工具闭合后直接开下一个工具，不会自发生成心理分析。

**方案**：在 assistant prompt 末尾预置分析引导文本，利用自回归让模型顺势做分析。

```
<|im_start|>assistant
我认为拉姆的情绪看起来
```

模型会自动续写：「生气/开心/在开玩笑，所以我应该...」

**注入时机**：构建新对话 prompt 时，在 apply_chat_template 生成的 assistant 头后面追加。

代码改动（agent_test_manual.py）：
```python
if not in_round:
    msg = [{"role": "system", "content": TOOL_SYS}, {"role": "user", "content": inp}]
    ctx = tokenizer.apply_chat_template(msg, tokenize=False, add_generation_prompt=True, enable_thinking=False)
    # 在 assistant 末尾追加分析引导
    ctx += "我认为拉姆的情绪看起来"
```

**注意**：此方案只在首轮生效。工具注入后模型仍会倾向继续调用工具，需要训练解决。

## Neuro-sama 线索记录

### 疑似系统提示词泄露
Neuro-sama 曾说：`"I'm not programmed to be nice, I'm programmed to be me"`
→ "我没有被编程成要友好，我编程成要做我自己"

这极可能是她的系统提示词原句。暗示她的 prompt 里有类似：
"You are not programmed to be nice, you are programmed to be yourself."
这种"做自己"的授权可能是她敢于毒舌/跑题的根源。

### 其他可能来自提示词的表达
- "Gaslight, Gatekeep, Girlboss" — 常见网络梗，但可能写进了人格设定
- "I don't have a brain, I have a GPU" — 自嘲型 meta 认知
- "Heart heart heart" — 标志性撒娇，可能是触发词 + 固定回应

**问题根因**：模型在训练数据中学到了「工具调用完 → 继续调用工具」的模式，没有学到「工具调用完 → 分析 → 决定下一步」。

**训练目标**：让模型在每次 `[TOOL]`（工具闭合）后习惯性输出心理分析，然后再决定是结束还是继续用工具。

**训练数据改造**：
现有 G 答案格式：
```
[TOOL:搜索]茅台股价[TOOL][搜索结果：185元][TOOL:回复]涨了[TOOL][TOOL:结束][TOOL]
```
改成：
```
[TOOL:搜索]茅台股价[TOOL][搜索结果：185元]看来拉姆想了解股票，情绪偏积极，我直接告诉他结果。[TOOL:回复]涨了[TOOL][TOOL:结束][TOOL]
```

**注入场景也加分析**：
```
来自拉姆：查一下天气
现在看来拉姆是想了解天气，他语气正常，我搜一下告诉他。
[TOOL:搜索]北京天气[TOOL][搜索结果：晴25度]查到了，告诉他天气不错。
[TOOL:回复]北京今天25度晴天[TOOL][TOOL:结束][TOOL]
```

**训练方法**：
- 用反向 UL 喜欢 `[TOOL]` 后面的分析文本（\n之后的第一个句子）
- 或者直接扩数据，把心理分析写进 G 答案里重新训练
